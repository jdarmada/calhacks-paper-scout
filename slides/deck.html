Three ways to search

You want all three.

Keyword · BM25

Exact words

Unbeatable for names, acronyms, error codes, and jargon like “transformer”.

Semantic · Jina

Meaning

“teach robots by watching humans” finds imitation learning from video demonstrations, with zero shared words.

Hybrid + rerank

Best of both

Run both, fuse with RRF, then a reranker reads the top hits and reorders them. This is what you ship.

⬢ elastic
Serverless + Jina

The whole setup is one field.

// PUT /papers
{
  "mappings": {
    "properties": {
      "title":   { "type": "text" },
      "authors": { "type": "keyword" },
      "content": { "type": "semantic_text" }
    }
  }
}

When you index a document, Elastic automatically:

  • chunks long text
  • embeds it with Jina v5 on Elastic's inference service
  • stores and indexes the vectors

No embedding API key, no vector DB, no chunking library. Multilingual out of the box.

Tools are where the magic is

Four kinds of tools.

INDEX SEARCH

“Here's an index, figure it out.” The agent writes its own queries.

ES|QL

Your query, with blanks the agent fills in. Guardrails for analytics.

WORKFLOW

Lets the agent take actions, not just answer.

MCP

Every tool is auto-exposed to Claude Code, Cursor, or your app.

{ "id": "papers_topic_trend", "type": "esql",
  // ↓ the agent picks tools by reading this

  "configuration": { "query": "FROM papers | WHERE MATCH(abstract, ?topic) | STATS COUNT(*) BY month" } }

Elastic Workflows

Agents that act.

name: paper-digest
triggers:
  - type: manual
  - type: scheduled       # every morning
    with: { every: 1d }
steps:
  - name: find_papers
    type: elasticsearch.search  # Jina semantic
  - name: write_digest
    type: ai.agent              # reason
    with:
      message: "Brief me on {{ inputs.topic }}
                using {{ steps.find_papers.output }}"
  - name: save_digest
    type: elasticsearch.index   # or Slack, Jira...

Runs on a schedule and is a tool the agent can call.
